## 功能概览

- 五阶段关卡推进：每清空当前阶段所有脑子后进入下一阶段，红线向右推进，植物布局逐步增强。
- 三类可投放僵尸：普通僵尸、铁桶僵尸、撑杆跳僵尸，分别有独立价格、冷却与行为。
- 多种植物交互：向日葵死亡后掉落阳光，豌豆射手和双发射手会检测同一行右侧目标并发射豌豆，坚果墙低血量后切换破损贴图。
- 卡牌系统：点击卡牌选中僵尸，点击红线右侧合法格子投放；投放成功后扣除阳光并进入冷却。
- 失败判定：当仍有脑子存活，但场上没有可推进僵尸、没有可收集阳光，并且阳光不足以购买最低价僵尸时判负。
- 对象生命周期管理：所有游戏对象由 `GameWorld` 统一保存和清理，更新过程中产生的新对象先进入临时队列，避免遍历容器时修改主对象列表。

## 核心设计

### GameWorld 作为统一调度中心

`GameWorld` 继承课程框架的 `WorldBase`，负责保存全局状态、对象容器、文本 UI、植物格子索引、卡牌状态和脑子存活状态。每一帧的主流程为：

1. 更新卡牌冷却。
2. 调用所有对象自己的 `Update()`。
3. 将本帧新创建的对象合并进主对象容器。
4. 删除已标记死亡的对象。
5. 检查阶段完成、胜利或失败条件。
6. 刷新文字 UI。

这种结构把“谁拥有对象”和“对象如何表现”分开：对象通过 `GameWorld` 请求创建豌豆、扣植物血量、收集阳光或吃掉脑子，但对象本身不直接管理全局容器。

### GameObject 继承体系

所有可更新或可点击对象都继承 `GameObject`，再进一步分成植物、僵尸、投射物、阳光和 UI 对象。代码通过 `ObjectCategory`、`AsPlant()`、`AsZombie()` 等虚函数识别对象类别，避免在主要逻辑中依赖 `dynamic_cast` 或 `typeid`。

### 僵尸行为

- `RegularZombie` 复用基础僵尸逻辑：向左移动、碰到植物后啃食、碰到脑子后完成该行目标。
- `BucketZombie` 在普通僵尸基础上增加高血量和掉桶贴图切换。
- `PoleVaultingZombie` 使用 `RUN`、`JUMP`、`WALK`、`EAT` 四状态状态机，先快速奔跑，遇到第一株植物时跳过，之后按普通速度前进或啃食。

### 植物行为

- `Sunflower` 被吃掉时生成 6 个阳光，每个价值 `SUN_VALUE`。
- `ShootingPlant` 抽象出射击冷却和同一行目标检测，`Peashooter` 发射一颗豌豆，`Repeater` 重写发射数量为两颗。
- `WallNut` 血量较高，并在生命值低于三分之一时切换破损贴图。

## 玩法说明

1. 点击顶部僵尸卡牌选择要投放的僵尸。
2. 在红线右侧合法草坪格中点击投放。
3. 僵尸会向左推进，遇到植物时自动啃食，吃掉本行脑子后该行目标完成。
4. 向日葵死亡后会掉落阳光，点击阳光可以补充资源。
5. 吃掉当前阶段所有脑子后进入下一阶段；完成第 5 阶段后胜利。
